# Передача проекта

Документ для ассистента, который продолжит работу над этим лендингом.
Написан после первой итерации разработки, состояние на коммит `f852ef8`.

---

## 1. Что это

Одностраничный лендинг архитектурного бюро **STOLYAROV** (Антон и Мария Столяровы,
дизайн интерьеров квартир и загородных домов, Москва).

Это **новая версия** сайта, сделанная по мотивам текущего рабочего сайта
`stolyarov.pro` — та же структура и тексты, но более современная подача.
Текущий боевой сайт **не тронут** и работает отдельно.

Заказчик — владелец бюро, **не разработчик**. Формулирует задачи на уровне
«сделай крупнее», «мы должны занимать столько же места, сколько текст».
Технические решения принимает ассистент, но композицию и дизайн заказчик
оценивает по скриншотам и правит словами.

## 3. Стек и как это устроено

**Чистые HTML + CSS + JS. Никакой сборки, зависимостей, npm, фреймворков.**
Это осознанное решение: заказчик не технический, сайт должен открываться двойным
кликом по `index.html` и заливаться на любой хостинг простым копированием файлов.
**Не предлагать React/Vite/Tailwind/сборщики** — это сломает весь рабочий процесс.

```
index.html                              вся разметка страницы
assets/css/style.css                    все стили
assets/js/main.js                       единственный скрипт — лайтбокс галереи
assets/img/team.png                     портрет Антона и Марии (прозрачный фон)
assets/img/LOGO-WHITE-TRANSPARENT.png   лого для тёмного фона (используется)
assets/img/LOGO-BLACK-TRANSPARENT.png   лого для светлого фона (про запас)
assets/img/projects/<слаг>/01..06       фото проекта по порядку показа
CLAUDE.md                               краткая справка по коду
```

**Запуск локально:** открыть `index.html` в браузере, либо
`python3 -m http.server 8000` в корне.

**Деплой:** `git push` в ветку → GitHub Pages обновляется сам за минуту-две.
Никакого CI, сборки, шагов между пушем и живым сайтом нет.

### Структура страницы

1. **Шапка** (`.topbar`) — логотип, строка «Дизайн интерьеров... · Москва · 2026», телефон
2. **Первый экран** (`.hero`) — фон-фото, заголовок, абзац, кнопка, дисклеймер, портрет
3. **Преимущества** (`.advantages`) — 3 блока с SVG-иконками
4. **Портфолио** (`.portfolio`) — сетка карточек во всю ширину экрана
5. **Лайтбокс** (`.lightbox`) — модальное окно галереи, скрыто до клика

### Как устроена галерея

Весь контент галерей объявлен прямо в `main.js` объектом `galleries`,
ключ — слаг проекта:

```js
var galleries = {
  "chistye-prudy": {
    title: "Фахверк в КП «Чистые пруды»",
    sub: "Чистые пруды, 3",
    images: [ { src: "assets/img/projects/chistye-prudy/04.webp", alt: "Гостиная-столовая" }, ... ]
  }
};
```

Чтобы добавить новый проект, нужно согласовать **три места по одному слагу**:

1. Положить фото в `assets/img/projects/<слаг>/01.webp, 02.webp, ...`
2. Добавить запись `galleries["<слаг>"]` в `main.js`
3. Добавить `<article class="project-card" data-gallery="<слаг>">` в `.portfolio__grid`
   в `index.html` — с обложкой `<img>` и подписью `.project-card__info`

Клик по любому месту `.project-card__media` открывает лайтбокс с нулевого кадра.
Лайтбокс умеет: стрелки, клавиатуру (←/→/Esc), свайп, ленту миниатюр,
кроссфейд между кадрами, закрытие по клику на фон. Специально сделан так, чтобы
**показать проект не уводя посетителя со страницы** — это было прямое требование.

## 4. Решения, которые нельзя молча откатывать

Каждое из них — результат правки конкретной проблемы. Если менять, то осознанно.

**Единая сетка через `--gutter`.**
Переменная в `:root` задаёт боковой отступ. Её используют шапка (`.topbar__inner`)
и **обе** колонки первого экрана. Благодаря этому левый край логотипа совпадает с
левым краем заголовка, а телефон — с правым краем портрета.
Раньше шапка сидела в `.container` (1240px по центру), а первый экран был во всю
ширину — на мониторе 2560px логотип начинался на ~400px, а заголовок на ~80px.
Выглядело как две разные страницы. **Не возвращать `.container` в шапку или в
`.hero__inner`.**

**Первый экран — настоящие 50/50 на десктопе.**
С `min-width: 1080px` `.hero` это flex-строка, `.hero__inner` и `.hero__team`
имеют `flex: 0 1 50%`. Текст прижат к верху левой половины (`align-self: center`),
портрет — к низу правой (`align-self: flex-end`). До этого портрет висел
`position: absolute` поверх правого края и перекрывался с текстом.

**Мобильная версия — отдельная композиция, а не сжатый десктоп.**
До 1080px `.hero` это колонка: текст, кнопка, под ними портрет во всю ширину.
Заказчик согласовал этот вид по скриншоту своего телефона. **Не ломать.**

**Типографика на `clamp()`, а не на брейкпоинтах.**
Размеры шрифтов, отступы и кегли привязаны к `vw` через `clamp()`, чтобы
непрерывно расти от телефона до 2K. Потолки специально подняты высоко: при
низких потолках на 2560px шрифты упирались в максимум, а портрет продолжал расти
вместе с колонкой и визуально «съедал» текст. **Не заменять на фиксированные
значения по брейкпоинтам.**

**Затемнение фона (`.hero__scrim`) сделано под конкретную композицию.**
На десктопе это радиальное пятно под текстом слева плюс виньетки сверху и снизу —
чтобы фотография фона (латунная люстра, глубина комнаты) читалась за портретом.
На мобильной версии другой, более простой градиент. Если менять композицию
первого экрана — затемнение придётся пересчитывать вместе с ней.

**Фон первого экрана — то же самое фото, что и в галерее** (`chistye-prudy/04.webp`),
отдельного файла нет. Это не ошибка.

**Кнопка «Рассчитать стоимость» намеренно не подключена.**
Обработчик `[data-cta="calc"]` в `main.js` пишет в консоль и больше ничего не
делает. Заказчик просил пока не подключать Marquiz. **Это не баг.**

**Подпись «Антон и Мария Столяровы» на портрете удалена намеренно.**
Раньше она позиционировалась в процентах и попадала на руку мужчины, а на других
ширинах экрана заехала бы на лицо. Прозрачные зоны в `team.png` есть только в
верхней трети, а она первой обрезается на низких экранах — надёжного места нет.
Плюс имена уже есть в тексте строкой выше. Если возвращать — нужен рукописный
шрифт, как на текущем сайте, иначе читается как подпись к фото, а не как автограф.

## 5. Заглушки и незаконченное

**Портфолио: 4 карточки, но реальный проект один.**
Галерея `chistye-prudy` намеренно продублирована во все 4 карточки, пока нет
фото других объектов. Заказчик об этом знает и согласовал как временное решение.

**Нет фото сауны.**
`assets/img/projects/chistye-prudy/01.svg` — это **не картинка проекта**, а
заглушка: серый прямоугольник с надписью, какое фото сюда должно встать.
Остальные `02–06` — настоящие фото в `.webp`. Когда придёт фото сауны, заменить
на `01.webp` и поправить путь в `main.js`.

**Marquiz не подключён** — см. выше.

**Секции ниже первого экрана не проходили дизайн-ревью.**
Первый экран переделывался по замечаниям несколько раз, а «Преимущества» и
«Портфолио» остались в виде первого черновика: фиксированные размеры шрифтов,
`.container` на 1240px по центру (в отличие от первого экрана во всю ширину).

**Картинки не оптимизированы.** Суммарно ~3.3 МБ, из них `team.png` — 1.1 МБ.
Для лендинга это много. Нет `srcset`, нет ресайза под разные экраны,
нет `loading="lazy"`. Реальная проблема скорости, которой никто не занимался.

## 6. Известные проблемы дизайна (озвучены заказчику, не исправлены)

Заказчик их видел и отложил:

1. **Логотип и заголовок из разных шрифтовых миров.** Лого — узкий строгий
   гротеск, заголовки — Manrope 800, круглый и «айтишный». Для премиального
   интерьерного бюро тяжёлый bold спорен.
2. **Портрет выглядит «наклеенным»** — резкий край выреза, нет тени, нет сцепки
   с фоном.
3. **Нет индикатора прокрутки.** Первый экран ровно `100vh`, ничто не намекает,
   что ниже есть содержимое.

## 8. Как работать с этим заказчиком (практика)

Это сэкономит время — всё проверено на своих ошибках.

**Файлы он передаёт через веб-интерфейс GitHub.** Картинки, приложенные в чат,
дошли не полностью, зато загрузка через форму GitHub сработала с первого раза:
`https://github.com/irrreal-hue/Reposit-1/upload/claude/lendos-assembly-kgmtuw/incoming`
Заказчик кидает файлы с любыми именами, ассистент потом сам раскладывает и
переименовывает. Просить его соблюдать точные имена файлов — лишнее трение.

**Результат он смотрит на GitHub Pages.** Просто обновляет страницу после пуша.
Zip-архивы и ссылки на превью в облаке — хуже: в первом случае он смотрит
застывший слепок, во втором часть доменов у него блокируется.

**Перед правками он просит оценку.** Формулировка «оцени, что бы поправил,
перед тем как делать» была буквальной: сначала разбор с приоритетами, потом
он выбирает пункты, и только потом код.

**Проверять результат рендером, а не на глаз.** В контейнере есть headless
Chromium. Так нашлась проблема с потолками `clamp()`, невидимая в коде:

```bash
node -e "require('playwright')"   # запускать с executablePath: '/opt/pw-browsers/chromium'
```

Снимать минимум на трёх размерах: `2560x1300` (его монитор), `1440x820`,
`390x844`. Заказчик сидит на 2K — то, что нормально выглядит на ноутбуке, там
часто разваливается.
